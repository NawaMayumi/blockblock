# BlockBlock

赤いブロックをカメラに映すだけで、掛け算・たし算・ひき算の練習ができるブラウザアプリです。物理的なブロックを操作する体験(Physical Learning Blocks)と、デジタル画面での自動採点を組み合わせています。年長〜小学2年生くらいを想定しています。

**公開URL: https://nawamayumi.github.io/blockblock/**

## このアプリでできること

- **掛け算**: 赤いブロックを格子状(何段×何列)に並べると、カメラがその配置を読み取り「3 × 4 = ?」のように問題文だけを表示します(答えは表示しません)。
- **たし算・ひき算**: 決められた枠の中にブロックを置いて数を数えます。ひき算は「山からブロックを実際に取り除く」体験になっています。
- 答えは、黒いシール＋白い数字が書かれた「数字ブロック」をカメラに見せることで入力します。式の答えと数字ブロックが一致すると、正解の演出(アニメーション・音・スコア加算)が流れます。
- **カメラ映像や写真は一切外部に送信されません。** すべての処理は、今その処理をしている端末(スマホ・PC)の中だけで完結します。

## 動かしてみる

- そのまま使う: 上記の公開URLをスマホ・PCのブラウザで開いてください。カメラの利用を許可すると始まります。
- ローカルで動かす(コードを編集する人向け): このリポジトリの`dist`フォルダがアプリ本体一式です。

  ```bash
  cd dist
  python3 serve.py 8000
  # → http://localhost:8000 をブラウザで開く
  ```

  カメラを使うには「HTTPSで配信されている」か「localhostで開いている」かのどちらかが必要です(ブラウザ側のセキュリティ上の制約です)。スマホの実機で、ローカルで動かしているものを一時的に試したい場合は、`cloudflared tunnel --url http://localhost:8000`のようなトンネルツールで一時的なHTTPS URLを発行してください。

## 仕組み(実装の説明)

このアプリは、AIの画像認識サービスや専用のサーバー・データベースを一切使っていません。`index.html`・`app.js`・`styles.css`と、数字の見本画像(`digits/`フォルダ)だけでできている「静的サイト」で、ブラウザが標準で持っている機能だけで動いています。処理の流れは次の6段階です。

### 1. カメラ映像を1枚の「写真」として取り込む

ブラウザの`<video>`要素でカメラ映像を受け取り、毎秒約7〜8回、その瞬間の映像を`<canvas>`(絵を描くための透明な下敷きのようなもの)に描き写します。canvasに描いた画像は、1ピクセルずつの色情報(赤・緑・青の3つの数値。「RGB値」と呼びます)として取り出せるので、これ以降の処理はすべてこの数値の集まりに対して行います。

### 2. 色でブロックを見分ける(ピクセル分類)

画像の各ピクセルについて「これは赤いブロックの一部か?」を、RGBの数値を使った計算式で判定します。例えば「赤の成分が緑の成分よりだいぶ強い」「色の鮮やかさ(彩度)がある程度以上ある」といった条件です。木目調の机(オレンジっぽい色)は赤いブロックと色味が近いため区別が難しく、この計算式の"厳しさ"を調整するスライダーを設定画面に用意しています。数字ブロックの黒いシールや、判定用の黄色い印も同じ考え方で見分けています。

### 3. 隣り合う同じ色のピクセルを「1つのかたまり」にまとめる(連結成分)

色判定を通ったピクセルは画像のあちこちに散らばっているので、上下左右に隣り合っているもの同士を1つのグループにまとめます。これを「連結成分(connected component)」と呼びます。こうしてできた1つ1つのかたまりが、ブロック1個(またはブロック同士が密着している場合はそのかたまり全体)に対応します。

### 4. かたまりを行と列に整理する

複数のかたまりの中心位置を集めて、「近い高さにあるものは同じ行」「近い横位置にあるものは同じ列」という要領で自動的にグループ分けします。さらに、間隔・大きさ・色の濃さがどれだけ揃っているかを0〜1の「信頼度スコア」として計算し、これが一定以上でなければ「まだ綺麗に並んでいない」と判断して式を表示しません。適当に置いただけのブロックの並びを、誤って正しい式として認識してしまわないようにするためです。

ブロック同士がぴったりくっついて1つの大きなかたまりに見えてしまう場合は、そのかたまりの中の「色の濃さ」を横方向・縦方向にそれぞれ足し合わせてグラフにし、ブロック同士の隙間にできる影でわずかに色が薄くなる場所を谷として見つけることで、何個のブロックがくっついているかを推測します。

### 5. 答えの数字を読み取る(テンプレートマッチング)

数字ブロックの黒いシールも同じ要領で見つけ出し、28×28マスの小さな白黒の格子(ちょうど昔のゲーム機のドット絵くらいの解像度)に変換します。

これを、あらかじめ用意しておいた0〜9の実際の数字の形(SVGという、拡大しても輪郭が崩れないベクター画像形式のファイル)を同じ28×28の格子に変換した「お手本」10種類と比べ、一番形が近いものをその数字だと判定します。これは「テンプレートマッチング」と呼ばれる、機械学習モデルを使わずに実装できる古典的な画像認識手法です。フォント名を指定して描画する方式ではなく実際の数字の形をそのまま使っているのは、動作する端末にそのフォントが入っていない場合に、まったく違う書体に化けてしまう問題を避けるためです。

### 6. すぐに確定せず、少し待ってから答えを確定する

カメラ映像は手ぶれやピントのズレで、1コマ(フレーム)だけ誤判定することがあります。そのため「同じ判定が直近2秒間のうち7割以上続いたら確定」というルールを設けています。このように、瞬間的なノイズをならして安定した値を得る仕組みを「安定化(stabilization)」と呼びます。確定した後も、手が一瞬映り込むなどして判定が途切れても、1.6秒間は直前の確定結果を保持することで、表示がちらつかないようにしています。

### 全体の流れ

```
カメラ映像
  → ①色で分類(ピクセル単位のRGB判定)
  → ②隣り合う色をまとめる(連結成分)
  → ③行列に整理する(信頼度スコアで判定)
  → ④2秒安定したら確定
  → ⑤答えの数字ブロックと照合
  → ⑥正解演出
```

## 開発者向け: 外部からの答え取得

数字ブロックの答えが安定して確定すると、`window`へ`airwritingresult`イベントが発火します。

```js
window.addEventListener('airwritingresult', ({ detail }) => {
  // detail.value: 数値化された答え
  // detail.confidence: 平均confidence(信頼度、0〜1)
  // detail.confirmed: true
  // detail.cards: [{ value, confidence, x, y, w, h }, ...] (画面左→右の順)
});
```

`window.AnswerCards.getLatestResult()`でも直近の確定結果を取得できます(読み取り専用のフックで、カメラの起動・停止はアプリ本体のUIが握ったままです)。

## 既知の制約

- 色の判定基準(しきい値)は照明条件によって再調整が必要になることがあります。設定ドロワー内のスライダーで調整できます。
- ブロック同士が完全に密着していて影がほとんど出ない置き方だと、何個ぶんくっついているか判定できないことがあります。
- 3個以下のブロックの並びは、偶然の配置と区別できないため式(◯×◯=?)としては表示されません(個数のみ表示されます)。
- 数字ブロックに上下左右を判定する目印が無いため、上下逆に置くと「6」が「9」に誤読される可能性があります。
